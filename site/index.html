A distributed MQTT broker, Apache 2.0 licensed, all of it

Clustering, replicated queues, rules that carry messages to and from HTTP, and the admin interface are all in the one binary, under the Apache License 2.0. There is no enterprise edition and no open-core line: what is on this page is what you get. MQTT 3.1.1 and 5. Version 0.7.1.

What the sd-mqtt broker does

Apache 2.0, every feature
One licence over the whole repository and the whole binary. Clustering, replication, rules, authentication and the interface are not an upgrade; they are the product. The notices for everything compiled in ship inside every archive and image.
MQTT 3.1.1 and 5
Shared subscriptions, retained messages, wills, topic aliases and enhanced authentication, checked against Eclipse Paho's interoperability suite over TCP, TLS and WebSocket.
Durable when you give it a directory
Sessions, their subscriptions and their queued messages survive a restart, and no publisher is acknowledged before its message is on the disk.
Clustering
Nodes route to each other's subscribers, move a session to wherever its client reconnects, and keep each queue on more than one node. In synchronous mode, losing the node that owns a queue loses none of it.
Rules and connectors
Send matching messages to HTTP endpoints, accept HTTP posts as publications, poll an API, or bridge to another broker, with a durable outbox and dead letters for what could not be delivered.
Who may do what
Users with argon2 passwords or SCRAM-SHA-256, access control rules by user or client, API keys with read, write and admin scopes, and limits on publish rate and failed logins.
An interface in the broker
Live rates, connected clients, a topic browser that watches messages as they arrive, rule statistics, cluster health, and settings, served by the broker itself.

Run the MQTT broker

Either way you get a broker on port 1883 and its admin interface on port 1884.

In a container

The image is the static broker and nothing else. It refuses to start without an admin token, because inside a container the admin port is reachable from outside.

docker run -d -p 1883:1883 -p 1884:1884 \
  -v sdmqtt-data:/data \
  -e SDMQTT_ADMIN_TOKEN="$(openssl rand -hex 24)" \
  ghcr.io/clement880101/sd-mqtt:0.7.1

As a binary

Static builds for Linux on x86-64 and ARM, and builds for macOS. Each archive carries its checksum, the licence, and the notices for everything compiled in.

tar -xzf sdmqtt-0.7.1-x86_64-unknown-linux-musl.tar.gz
cd sdmqtt-0.7.1-x86_64-unknown-linux-musl
./sdmqtt serve --store-directory ./data

Questions

Is sd-mqtt free for commercial use?
Yes. The whole repository and the whole binary are under the Apache License 2.0, including clustering, queue replication, rules, authentication and the admin interface. There is no enterprise edition and no feature behind a commercial licence.
Which MQTT versions does sd-mqtt support?
MQTT 3.1.1 and MQTT 5, over TCP, TLS, WebSocket and secure WebSocket. Shared subscriptions, retained messages, wills, topic aliases and enhanced authentication with SCRAM-SHA-256 are included, and the broker is checked against Eclipse Paho's interoperability suite.
How is sd-mqtt different from Mosquitto?
Mosquitto is a single-node broker that links brokers by bridging. sd-mqtt is a cluster: nodes route publications to each other's subscribers, a session follows its client to whichever node it reconnects to, and each queue is kept on more than one node. It also ships rules to and from HTTP and an admin interface in the same binary.
How is sd-mqtt different from EMQX?
From version 5.9, EMQX is under the Business Source License 1.1, which allows one node in production and needs a commercial licence to run a cluster. sd-mqtt is under the Apache License 2.0 and its clustering is free to run at any size.
Does sd-mqtt need a database or other services?
No. It is one static binary with an embedded store: give it a directory and sessions, subscriptions, queued messages, retained messages, rules and users survive a restart. Without a directory it runs in memory.
Which platforms does sd-mqtt run on?
Linux on x86_64 and aarch64 as a static binary, macOS on Apple silicon and Intel, and a container image for amd64 and arm64. There is no Windows build.
How do I run an MQTT cluster with sd-mqtt?
Start three nodes with the same cluster name and secret, each listing the others as seeds. The setup guide in the repository takes a Docker Compose file from nothing to a three-node cluster in six steps.
Is sd-mqtt ready for production?
It is at version 0.7.1, before 1.0. The protocol and clustering are tested, but until 1.0 the stored format may change between releases, and a store written by an earlier build is refused rather than migrated. Read the changelog before upgrading.
