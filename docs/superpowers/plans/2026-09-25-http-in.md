# Ingest Connector Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An HTTP post reaches an MQTT subscriber, and survives a broker
restart mid-flight. That is the second half of milestone four's exit
criterion.

**Architecture:** A separate ingest listener, so that accepting data does not
require exposing the administrative surface. Every route on it is guarded by
its own rule's bearer token, so the listener needs no address rule of its own.

**Tech Stack:** The axum router already in the admin crate, refactored so a
route set can be served on a second address.

## Three things decided before you start

**A rule without a token is refused, at creation and at route
registration.** The endpoint publishes. The admin listener's own refusal does
not transfer, because an ingest token is per rule rather than per listener,
so the refusal has to move to where a rule is accepted. A tokenless rule
must have no route at all rather than an open one.

**The host check is a blanket layer over the admin router.** On an ingest
listener it would mean an operator adding every webhook sender's hostname or
seeing every delivery refused in a way that looks like a bug. Not applying it
there is defensible, because every ingest route is individually guarded, but
it must be a written decision rather than an omission. Decide, and write it
where a reader will meet it.

**The body limit must agree with the broker's maximum packet size.** If they
disagree, ingest accepts a body the broker then refuses to publish, and the
caller is told the post succeeded.

### Task 2: A route set can be served on a second address

**Files:**
- Modify: `crates/admin/src/lib.rs`
- Test: the same file

The admin crate builds one router from health, resources, events, taps and
assets, and serves it. There is no seam for serving a different route set on
a different address.

Factor one out. This is the first task rather than an afterthought because
every later task needs it, and because a seam added afterwards tends to be
shaped by whatever was easiest at the time.

**No new axum feature is needed.** Path parameters and raw bodies are
unconditional.

- [ ] **Step 1: Write the failing test**

Two listeners, each serving a different route set, and a route on one is not
reachable on the other. That last clause is the test: a seam that serves
everything everywhere passes anything weaker.

- [ ] **Step 2: Implement, run, confirm teeth**

Mutations: serve the admin routes on both; apply the host layer to both,
which is the decision above and must be visible as one.

- [ ] **Step 3: Commit**

```bash
git commit -m "feat(admin): a route set, served where it is asked for"
```

### Task 3: Ingest

**Files:**
- Create: `crates/rules/src/http_in.rs`
- Modify: `crates/rules/src/lib.rs`, `crates/sdmqtt/src/main.rs`, `crates/sdmqtt/src/config.rs`
- Test: those files

`POST /ingest/<rule-id>`, guarded by that rule's bearer token. The body is
published to a configured topic at a configured quality of service and retain
setting.

The topic may instead come from a named header or query parameter,
**restricted by a prefix so a caller cannot publish anywhere.** That
restriction is the whole safety of the feature: without it an ingest rule is
a way to publish to any topic on the broker, including the reserved ones.

- [ ] **Step 1: Write the failing tests**

- A post with the right token publishes to the configured topic, and an MQTT
  subscriber receives it. That is the test that proves it went through the
  broker rather than somewhere parallel.
- No token, wrong token: refused.
- A rule configured with no token has no route: the path answers as though it
  does not exist, not as though it is unauthorised.
- A topic from a header is used. One outside the prefix is refused. One that
  tries to escape the prefix by any spelling you can think of is refused.
- A body over the limit is refused, and the limit agrees with the broker's.

The escape attempt is worth real thought. Write down which spellings you
tried.

- [ ] **Step 2: Publish through the path that already exists**

The admin crate's publish endpoint already goes through the same call a
connection uses. Use that, for the same reason it does: a second publish
implementation is a second set of rules about retention, expiry and matching,
and the two will drift.

An at-least-once ingest must wait for durability before answering, exactly as
the admin endpoint does. The response is a promise.

- [ ] **Step 3: Refuse a tokenless rule where a rule is accepted**

Not only at route registration. A rule stored without a token is a rule that
will be registered later, so the refusal belongs where rules are accepted too.

- [ ] **Step 4: Confirm teeth, commit**

Mutations: the token not checked; the prefix not applied; the prefix compared
by prefix-of-string rather than by topic level, which is how `a/bc` passes a
check meant for `a/b`; the durability wait skipped.

The third is the one that looks right and is not.

```bash
git commit -m "feat(rules): ingest, guarded per rule"
```

### Task 4: An HTTP post reaches a subscriber across a restart

**Files:**
- Modify: `crates/sdmqtt/tests/rules.rs`

The other half of the exit criterion, against the real binary.

1. Start the broker with a store, an ingest rule, and an MQTT subscriber with
   a durable session.
2. Disconnect the subscriber so its messages queue.
3. Post to the ingest endpoint at least once. It is acknowledged, so it is a
   promise.
4. **Kill the broker.**
5. Start it again. The subscriber reconnects and receives the message.

Kill, do not stop. A clean shutdown flushes everything and proves nothing.

- [ ] **Step 1: Write it, watch it fail, then pass**

- [ ] **Step 2: Confirm teeth**

Answer the post before the durability wait and confirm the test fails. That
is the mutation the task exists for.

- [ ] **Step 3: Commit**

```bash
git commit -m "test: an HTTP post reaches a subscriber across a restart"
```
