# Cluster Mesh Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three nodes find each other, authenticate, and know when a peer has
gone. Plus the two test harnesses everything after this depends on: an
in-memory link, and a gate that can sever one direction of a real socket.

**Architecture:** A `cluster` crate holding identity, the handshake, the
framed link and the membership view. Nothing routes yet and nothing
replicates yet; this is the transport those sit on.

**Tech Stack:** `tokio`, `postcard`, `aws-lc-rs` for the keyed hash, `uuid`
v7. No new crates beyond naming the cryptography library that is already
linked.

## What is already decided

**The UUID is the identity everything orders by.** The name is for operators
and is never compared. Singleton ownership and the conflict tie-break must
read the same identity, so reconciling `singleton.rs` is part of this plan
rather than a later surprise.

**The handshake is a mutual challenge**, not a secret sent, because wrapping
the link in TLS is optional and a passive observer of one handshake would
otherwise learn the secret forever. The role byte is not decoration: without
it the answer is reflectable by an attacker who knows nothing, by opening a
connection back to the honest node and replaying its own challenge at it.

**No secret means no clustering.** Refused at startup, with no loopback
exemption, because unlike the admin listener there is no zero-configuration
case to preserve.

### Task 2: The handshake

**Files:**
- Create: `crates/cluster/src/handshake.rs`, `crates/cluster/src/config.rs`
- Test: the same files

Two nonces, a role byte, and a keyed hash over a length-prefixed transcript
of a domain string, the role, the cluster name, both identities and both
nonces. Each side verifies before trusting; the listener verifies before
answering.

Name the cryptography library in the manifest. The research confirmed that
resolves with a byte-identical lock file and costs one direct dependency.

- [ ] **Step 1: Write the failing tests, including the attacks**

A matching secret authenticates both ways. A mismatched one is refused at
both ends, not just the listener, or a middle that never knew the secret
still gets a one-way link.

**Then the two attacks, because a handshake tested only on the happy path is
a handshake nobody attacked.** A captured transcript does not authenticate a
later connection. And an answer harvested in one role is the wrong answer in
the other, which is the reflection the role byte exists for: write that test
by actually performing the reflection, not by asserting the bytes differ.

A greeting carrying our own identity is refused.

Every length prefix earns its place: a test that no two distinct transcripts
produce the same bytes, by sliding a field boundary.

- [ ] **Step 2: Refuse to start without a secret**

Absent and empty are both refused, and the empty one is refused for being
empty rather than being read as absent. Three tests, as the admin listener's
equivalent has.

- [ ] **Step 3: Implement, confirm teeth, commit**

Mutations: the role byte dropped, which the reflection test must catch; the
nonce reused across connections; the listener answering before verifying;
an ordinary comparison in place of the constant-time one, and say whether a
test can see it.

```bash
git commit -m "feat(cluster): a link authenticates both ways, or not at all"
```

### Task 3: The framed link

**Files:**
- Create: `crates/cluster/src/frame.rs`, `crates/cluster/src/link.rs`
- Test: those files

A 32-bit little-endian length covering the version byte and the body, the
version byte, then a postcard-encoded message. Bounded by a configured
maximum. A version byte we do not know closes the link with a reason.

`crates/server/src/framing.rs` is the precedent for reading frames off a
stream incrementally and rejecting an oversized one from its declared length
alone, before allocating. Read it first.

Writes are batched and flushed on a size or time threshold. The outgoing
buffer per peer is bounded, and beyond the bound messages to that peer are
dropped and counted rather than blocking the sender.

- [ ] **Step 1: Write the failing tests**

A frame round trips. A frame declaring more than the maximum is refused from
its length alone, before anything is allocated. An unknown version closes
with a reason. A partial frame yields nothing and resumes when the rest
arrives. A full outgoing buffer drops and counts rather than blocking, and
the connection survives, which is the half that matters.

- [ ] **Step 2: Implement, confirm teeth, commit**

Mutations: the length excluding the version byte, which is the ambiguity the
spec had; the maximum checked after reading rather than before; a dropped
message not counted.

```bash
git commit -m "feat(cluster): frames, bounded in both directions"
```

### Task 4: The two harnesses

**Files:**
- Create: `crates/cluster/src/testing/memory.rs`, `crates/cluster/src/testing/gate.rs`
- Test: those files

Everything after this plan depends on being able to sever a link, so the
harnesses come before the mesh that uses them.

**The in-memory link** connects nodes in one process through duplex pipes
behind a switch, for the bulk of the matrix. Section 14 committed to this.

**The gate** puts one listener per ordered pair in front of a real socket,
with two independent flags deciding whether bytes move each way. It must:

- sever one direction while the other keeps flowing, **without closing
  either socket**, because a closed socket is a symmetric failure detected
  instantly and finds no bugs;
- heal on the same connection;
- offer a mode that stalls the sender rather than discarding, which is an
  overloaded peer rather than a black hole.

- [ ] **Step 1: Write the failing tests**

For each harness: one direction stops while the other flows; a full
partition; a partial partition among three where the third reaches both. For
the gate, the same against a peer in a separate process, because a gate that
only works in one process is not testing a socket.

- [ ] **Step 2: Implement, confirm teeth, commit**

Mutations: the gate closing the socket instead of swallowing, which the
heal-on-the-same-connection test must catch; a flag applying to both
directions.

```bash
git commit -m "test(cluster): an in-memory link, and a gate that cuts one way"
```

### Task 5: The mesh

**Files:**
- Create: `crates/cluster/src/mesh.rs`, `crates/cluster/src/membership.rs`
- Modify: `crates/sdmqtt/src/config.rs`, `crates/sdmqtt/src/main.rs`
- Test: those files

Nodes dial their seeds and each other, forming a full mesh. A node advertises
the address peers should dial, which is not its bind address.

Failure detection: a closed socket is immediate; a heartbeat every second
covers a half-open link; suspect after three missed, dead after ten seconds,
both configurable. Reconnection backs off with jitter, and a rejected secret
backs off harder than a transport failure.

**Two nodes dialling each other at once must settle on one link**, not two.
Decide the rule, make it deterministic from the two identities, and test it.

- [ ] **Step 1: Write the failing tests**

Three nodes over the in-memory link all see each other. A node killed is
seen dead by both others within the configured window. It rejoins. A
simultaneous dial settles on one link. A peer whose socket is open but silent
is declared dead by the heartbeat, which is the case the heartbeat exists
for and which a closed socket cannot reach.

- [ ] **Step 2: The metrics section 11.3 deferred**

The members gauge, and bytes sent, received and dropped on the links. The
router-match split waits for the plan that routes.

- [ ] **Step 3: Implement, confirm teeth, commit**

Mutations: a dead peer never removed; the heartbeat never sent; both
simultaneous dials kept.

```bash
git commit -m "feat(cluster): a mesh that knows who is there"
```
